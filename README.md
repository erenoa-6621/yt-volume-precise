# YT Volume Precise

YouTube の音量を **数値入力とプリセット**で操作する Chrome 拡張（Manifest V3）。

- 音量を `87` のように**数字で直接**指定する（ゲージを目分量で合わせない）
- よく使う音量を**プリセット**にして1クリックで当てる（既定 15 / 30 / 50 / 70 / 100）
- プレイヤーの中に小さなパネルを出す。**ポップアップと同じ部品**なので、どちらから操作しても同じ
- 100 を超える**ブースト**（最大 300）。既定は OFF で、明示的に ON にしたときだけ Web Audio を挿す
- 対応は `www.youtube.com` と `music.youtube.com`。ブラウザは Chrome / Edge（Chromium 系）。Firefox は未対応

## なぜ作るか（既存拡張があるのに）

機能では差別化できない。ストアには数値入力・プリセット・EQ を備えた拡張が既にある。
**作る理由は権限にある。**

- 音量ブースター系は、解析された不審拡張 109 本中 102 本が `<all_urls>` + `tabs` を要求している
- 2026-06、既存の Volume Booster にアフィリエイト注入コードが既定で追加された事例がある
- 典型的な壊れ方は「真っ当な拡張が売却・アカウント乗っ取りで悪性化する」
- インストール時の権限画面は、クリーンなものと悪性のもので **同一**

音量を変えたいだけの対価に、全サイトの閲覧履歴を渡す取引になっている。
本拡張はその取引を拒否する。

## インストール

Chrome ウェブストアには**提出していない**。現在の入手方法は、このリポジトリを clone して
「パッケージ化されていない拡張機能」として読み込むことだけ。

1. このリポジトリを clone する
2. `chrome://extensions` を開き、右上の「デベロッパー モード」を ON
3. 「パッケージ化されていない拡張機能を読み込む」を押し、**リポジトリの直下**（`manifest.json` が
   ある階層。`src/` ではない）を選ぶ
4. **すでに開いている YouTube のタブはリロードする。** content script は、拡張を入れたあとに
   読み込まれたページにしか入らない

詰まったとき・動作を1項目ずつ確かめたいときは **[INSTALL.md](INSTALL.md)** を見てほしい。
導入の細かい手順、失敗したときの読み方（DevTools のどこを見るか）、
動作確認のチェックリストがそこにある。

## 権限方針（本拡張の存在理由。機構で守る）

- `permissions` は **`storage` のみ**
- `host_permissions` は **`*://www.youtube.com/*` と `*://music.youtube.com/*` のみ**
- **外部通信をコードに一切持たない**（`fetch` / `XMLHttpRequest` / `WebSocket` / リモートコード実行を禁止）
- **npm 依存ゼロ・ビルド工程ゼロ**（サプライチェーン経路を作らない）

これらは README の約束ではなく `verify.sh` が機械検査する。破ると赤くなる。
**ただし4項目は保証の重さが違う。** 以前この節は4項目をまとめて「機械検査する」と書いていたが、
4つ目には検査が1行も無かった（`grep -c 'npm\|package.json\|node_modules' verify.sh` が `0` だった）。
本拡張が批判しているのは「文章の約束はあるが機構が無い」構造そのものなので、
**何が検査され、何が検査されないかを行ごとに書く。**

### 1. `permissions` は `storage` のみ ── 検査する（保証は重い）

`verify.sh` 項目4（`tools/scan_permissions.sh` / `tools/lib/manifest_scan.js`）。
manifest の**トップレベルキーをホワイトリスト**で検査しているので、`externally_connectable` の
ような知らないキーが1つ増えるだけで赤くなる。列挙した禁止語を避けても通れない。
**この4項目の中で最も強い保証はここにある。**

### 2. `host_permissions` は YouTube の2ホストのみ ── 検査する（保証は重い）

同じく項目4。`content_scripts` の `matches`・`host_permissions` の両方を検査し、
`<all_urls>` や第三のホストが入れば赤くなる。判定側・権限側・注入側が同じホスト集合かは
項目11（`test/integration.test.js` の継ぎ目3）が別途押さえる。

### 3. 外部通信をコードに持たない ── 検査する（**仕掛け線。証明ではない**）

`verify.sh` 項目5（`tools/scan_network.sh`）。

**検査する**：`fetch(` / `XMLHttpRequest` / `WebSocket` / `WebTransport` / `EventSource` /
`sendBeacon` / `RTCPeerConnection` / `RTCDataChannel` / `navigator.serviceWorker` /
`eval(` / `new Function` / `Worker(` / `createObjectURL` / `importScripts` / 動的 `import(` の字面。
YouTube 以外の `http(s)://` URL。プロトコル相対 URL（`//host.tld/`・**生 IPv4 `//1.2.3.4:8080/`**・
**生 IPv6 `//[2001:db8::1]/`** を含む）。走査対象の集合そのものも `tools/list_scan_targets.sh` として
切り出し、`src/` の外にファイルを置いて逃げられないようにしてある。

**検査しない**：`globalThis["fet"+"ch"]` のように**文字列連結や間接参照で API を再構成する**コード。
引用符の外で組み立てた URL。これは静的検査の原理的な限界であり、開示するしかない。
（生 IP 宛てのプロトコル相対 URL は「素の URL リテラル」でこの限界の**外**だったので、
開示ではなく規則を直して塞いだ。限界の名を借りて塞げるものを見逃さないこと。）

### 4. npm 依存ゼロ・ビルド工程ゼロ ── 一部だけ検査する（**ここが一番弱い**）

`verify.sh` 項目13（`tools/scan_supply_chain.sh`）。

**検査する**：`package.json` / `package-lock.json` / `npm-shrinkwrap.json` / `yarn.lock` /
`pnpm-lock.yaml` / `bun.lockb` / `node_modules/` が**リポジトリに存在しないこと**。
`webpack.config.*` / `vite.config.*` / `rollup.config.*` / `esbuild.*` / `gulpfile.*` /
`babel.config.*` / `.babelrc` / `tsconfig.json` / `jsconfig.json` / `Makefile` が**存在しないこと**。
`src/` の `.js` に **ESM の `import` / `export` 文が無いこと**（SPEC 第0章「content script は
classic script」の裏返し。トランスパイル前提のコードが混入していないことの傍証）。

**検査しない（重要）**：
- **配布物がこのソースそのものである保証はしない。** 見ているのは作業ツリーだけで、
  Chrome ウェブストアに提出する zip や他人が配る版が同じ中身かは何も言えない。
  それを言うには再現ビルドと署名の照合が要る。**現時点でこの拡張はその検査を持っていない。**
- **「ビルド工程が無い」を直接は証明していない。** 証明しているのは「よくあるビルド設定の
  ファイル名が無い」ことだけである。設定名の列挙は必ず追いつかなくなるし、CI の YAML に
  ワンライナーのバンドルを書く形は検出できない。
- **「依存ゼロ」も直接は証明していない。** 他人のコードを `src/` に直接貼り付ける
  （ベンダリング）と依存の成果物は1つも残らない。字面では区別できない。

**まとめると、保証の重さは 1・2 ＞ 3 ＞ 4 である。**
1・2 は「知らないものが増えたら赤くなる」ホワイトリストなので強い。3 と 4 は
「知っている悪いものを列挙して探す」ブラックリストなので、原理的に漏れる。
`verify.sh` が緑であることを「安全である証明」と読まないこと。

## 検査の回し方

リポジトリの直下で:

```
./verify.sh ; echo "exit=$?"
```

`exit=0` が全緑。最終行に `pass=N fail=0` の形で件数が出る。
**N は検査を足せば増える。見るのは `fail=0` と `exit=0`。**

何を検査しているかの一覧は、この README には書かない（手で写した一覧は必ず腐る）。
現物は実行したときの出力そのものなので、これを打つ:

```
bash verify.sh | grep -E '^\[(OK|NG)\] '
```

必要なのは `bash` と `node` だけ（npm も、ブラウザを起動する仕掛けも使わない）。
回帰スイートを含むため、全体の実行には数分かかる。

**緑が保証しないこと**：`verify.sh` は Node 上の偽 DOM・偽 `chrome` に対して走る。
実ブラウザも実 YouTube も一切触っていないし、実際のネットワーク通信も見ていない
（コードの静的検査のみ）。YouTube 側の DOM やイベント名が変わったことも検知できない。
**緑は「ブラウザで動く」の意味ではない。**

## 既知の限界

- **実機での確認は限定的である。** ブラウザで一通り触った版はあるが、
  [INSTALL.md](INSTALL.md) の動作確認チェックリストには**未確認のまま残っている項目が多い**。
  とくに 100 超のブースト（Web Audio）が実際にどう鳴るか（音割れ・無音・元に戻せるか）は
  確かめられていない。
- **設計の前提に1つ、実機で未確認のものがある。** ポップアップは「`tabs` 権限なしでも
  `chrome.tabs.query` が YouTube タブの `url` を返す」という前提の上に立っている。
  これが外れると、拡張はまるごとオフライン表示に落ちる。
- **YouTube の DOM に依存している部分がある。** プレイヤー内のボタンは
  `.ytp-right-controls` に差し込む。見つからなければ黙って浮きハンドルに戻る設計だが、
  「黙って戻る」ので気づく機構は無い。
- **静的検査はブラックリストの部分がある**（上の権限方針3・4）。

**穴の全在庫は [KNOWN_GAPS.md](KNOWN_GAPS.md) にある。**
直せるのに直していないもの・原理的に直せないものを区別して、実測値つきで並べてある。
**この一覧が空であることは、安全の証明にならない。測っていないだけかもしれない。**

フォルダを読み込めば**ディスク上には同梱される**。
